Next-Word Prediction: Building and Evaluating the Model

Hein Htet Linn Nyan

2026-09-24

Summary

The model suggests the next word from the last three words typed. The best version tested puts the correct word in its top three suggestions 24% of the time. The version chosen for the app is nearly as accurate (24%), takes 18.5 MB of memory and returns suggestions in 8.52 milliseconds.

How the model works

The model learns from counts of short word sequences (n-grams) in the training text: single words, and runs of two, three and four words. To predict, it looks up the last three words typed and finds which words most often followed them. If that three-word phrase never appeared in training, it drops the oldest word and tries again with two, then one. Each step down is scored lower, so matches on longer phrases win. This method is called “stupid backoff”. It is simple and fast, and works well on large text collections.

Words seen only once in training are treated as a single “unknown word” token. Only the top five candidates for each phrase are kept, since the app shows three.

How it was tested

Before training, 5,000 lines were set aside and never used to build the model. From these, 20,000 positions were picked at random. At each one, the model was given the preceding words and asked for the next.

Four measures were recorded:

  • Top-1, top-2, top-3 accuracy: how often the correct word was the first suggestion, in the first two, or in the first three.
  • Perplexity: how surprised the model is by the real text, on average. Lower is better.
  • Speed: milliseconds per prediction, averaged over 300 single predictions.
  • Size: memory used by the tables the app needs.

Nine versions were compared: three training sizes (1%, 3% and 5% of the data) crossed with three pruning levels. Pruning drops word sequences seen fewer than 2 or 4 times in training.

More data or a bigger model?

More training data raises accuracy at every pruning level. The gain is modest, which is typical: common phrases are learned from a small sample, and more data mostly adds rare ones.

Does accuracy cost speed?

Prediction time ranged from 7.31 to 8.8 ms. All versions are fast enough to update as the user types. Speed is not the limit here; memory is.

Does perplexity agree with accuracy?

The correlation between perplexity and accuracy was -0.49 for top-1 and -0.56 for top-3. A negative value means lower perplexity goes with higher accuracy, as expected. The match is not exact, for two reasons. Perplexity scores the probability the model gives the right word, while accuracy only asks whether the right word made the top three. And each training size has its own vocabulary, which shifts perplexity in ways that do not affect accuracy.

Can the model be made smaller?

Yes. With 3% of the data, dropping sequences seen fewer than 4 times cut the model size by 98% and lowered top-3 accuracy by -0.8 percentage points. Most of the size comes from phrases seen once, which rarely help predict anything.

Chosen model

The app will use the model trained on 3% of the data with a minimum count of 2. It is the smallest version within half a percentage point of the best accuracy.

MAX_ORDER <- 4
ALPHA     <- 0.4

clean_text <- function(x) {
  x |>
    stri_trans_tolower() |>
    stri_replace_all_regex("https?://\\S+|www\\.\\S+", " ") |>
    stri_replace_all_regex("[\\u2018\\u2019]", "'") |>
    stri_replace_all_regex("[^a-z' ]", " ") |>
    stri_replace_all_regex("(^| )'+|'+( |$)", " ") |>
    stri_replace_all_regex(" +", " ") |>
    stri_trim_both()
}

map_vocab <- function(w, vocab) {
  w[!(w %chin% vocab)] <- "<unk>"
  w
}

ctx_key <- function(cases, n) {
  if (n == 1) return(rep("", nrow(cases)))
  parts <- lapply(rev(seq_len(n - 1)), function(k) cases[[paste0("w", k)]])
  key <- do.call(paste, parts)
  key[Reduce(`|`, lapply(parts, is.na))] <- NA_character_
  key
}

predict_batch <- function(model, cases, k = 3) {
  parts <- list()
  for (n in MAX_ORDER:2) {
    q <- data.table(id = cases$id, prefix = ctx_key(cases, n))[!is.na(prefix)]
    hit <- model$pred[[n]][q, on = "prefix", nomatch = 0L, allow.cartesian = TRUE]
    if (nrow(hit)) parts[[length(parts) + 1]] <-
      hit[, .(id, word, score = ALPHA^(MAX_ORDER - n) * p)]
  }
  u <- model$pred[[1]]
  parts[[length(parts) + 1]] <- data.table(
    id    = rep(cases$id, each = nrow(u)),
    word  = rep(u$word, times = nrow(cases)),
    score = rep(ALPHA^(MAX_ORDER - 1) * u$p, times = nrow(cases))
  )
  cand <- rbindlist(parts)[, .(score = max(score)), by = .(id, word)]
  setorder(cand, id, -score)
  cand[, rank := rowid(id)][rank <= k]
}

predict_next <- function(model, phrase, k = 3) {
  w <- stri_split_fixed(clean_text(phrase), " ", omit_empty = TRUE)[[1]] |>
    map_vocab(model$vocab) |>
    rev()
  cases <- data.table(id = 1L,
                      w1 = as.character(w[1]),
                      w2 = as.character(w[2]),
                      w3 = as.character(w[3]))
  predict_batch(model, cases, k)$word
}
